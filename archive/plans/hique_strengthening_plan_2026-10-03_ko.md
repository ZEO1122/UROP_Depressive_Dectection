# HiQuE 보강 실험 계획: 입력 검증 → 손실 분리 → 계층 검증

> 보존된 과거 계획이다. 실행 여부와 실제 조건은 [실험 목록](../../experiments/README.md)의 결과 기록을 우선한다.

실행 완료 기록: [V3 결과 보고서](../../experiments/hique/v3_input_study/dev_results.md). 다섯 조건×다섯 시드×100epochs를 완료했다. 학습 전 발견한 토크나이저 로딩 오류는 E0를 포함한 모든T에 수정했고 amendment로 기록했다. 아래는 실행 전 계획을 보존한 것이다. 2단계의 추가 ASR/계층 실험은 이번 실행 범위에 포함하지 않았다.

2026-10-03. **계획만 작성했으며 새 특징 추출·학습·평가는 실행하지 않았다.** 원인 진단은 [성능 격차 보고서](../../docs/hique_diagnosis.md)를 기준으로 한다.

## 1. 목표와 원칙

우선 목표는 성능을 올릴 수 있는 입력 경로를 확보하고, 개선 또는 악화가 어느 변경에서 나오는지 구분하는 것이다. 논문0.79 달성을 목표로 설정을 고르지 않는다. 원 논문 재현과 정보 보존을 개선한 변형을 별도로 명명한다.

1. 기존 코드·결과·가중치는 보존한다. 새 코드는 `hique3_*`, 새 산출물은 `Data/hique_input_study_v3/`로 분리한다.
2. 참가자·모델·시드·학습 예산을 맞춘다. 단계 사이에 여러 요인이 달라지면 묶음 개입이라고 명시한다.
3. 제공 전사의 화자·시간을 출발점으로 삼되 알려진 전사 누락·시각 오류를 자동으로 정답이라고 보증하지 않는다.
4. 본 단계는 train/dev 진단이다. 이미 본 test를 다시 미노출 자료라고 부르지 않는다.
5. 계층 정보를 계속 바꾸기 전에 입력부터 검증한다. 표준화는 단독 진단에서 일관된 회복이 없었으므로 첫 보강 변수로 삼지 않는다.

근거: [진단보고서 §2–5](../../docs/hique_diagnosis.md); `experiments/hique2_asr.py:24`, `hique2_data.py:64`, `hique2_data.py:154`, `hique2_train.py:80`, `hique2_network.py:26`.

## 3. 0단계: 학습 전에 질문–답변 사건 표를 검증

### 입력을 다시 정의

제공 전사에서 speaker/start_time/stop_time/value를 직접 읽는다. 물음표로 화자를 바꾸지 않는다. 각 사건을 다음 형태로 보존한다.

`participant_id, split, source_row_ids, raw_question, canonical_question_id, question_type, preceding_question_event_id, root_primary_event_id, followup_depth, answer_row_ids, answer_intervals, answer_text, mapping_status`

- 질문이 반복돼도 사건 표에서는 덮어쓰지 않는다. 모델용 슬롯을 만들 때만 첫/마지막/전체 정책을 적용한다.
- Ellie의 질문·요청과 단순 맞장구를 구분한다. 맞장구가 나왔다고 진행 중인 응답의 부모 질문을 바꾸지 않는다.
- ID 접두어·괄호 표기를 공식 문서에 따라 정리하되 원문과 source row는 남긴다.
- `scrubbed_entry`·인식불가 표시는 따로 기록하고, 비식별화 음성을 복원하거나 내용을 추측하지 않는다. 필터 규칙은 모든 비교 조건에 일관되게 적용하고 제외량을 보고한다.
- 질문 매핑은 train에서 출처를 확인한 정규형·별칭 표를 먼저 만든다. 의미가 불확실한 문장은 후보와 근거를 남기고 `unknown`으로 관리한다. 일치하지 않는 문장도 무조건85개 중 하나로 강제 배정하지 않는다.
- `unknown` 원문은 사건 표에 보존한다. 85슬롯 모델에 배치하지 못한 정보량은 별도로 보고하고, '전체 응답 보존'은 **매핑된 질문의 모든 답변**이라는 범위를 명시한다.
- 새 질문이지만 매핑되지 않은 `unknown_question`은 직전 답변 구간을 종료한다. 이후 답변은 그 unknown 사건에 연결하며 앞선 알려진 질문 슬롯에 섞지 않는다. 질문인지 맞장구인지도 불명확한 Ellie 발화는 불확실한 경계로 기록해 보수적으로 분리한다. 명시적으로 확인한 맞장구만 기존 사건을 유지한다. Unknown 뒤에 나오는 후속 질문의 부모도 불명확하면 unknown 관계를 남기고 앞선 알려진 root로 임의 연결하지 않는다.
- Dev에서는 고정한 규칙을 적용한다. Dev 성능을 보고 매핑이나 별칭 표를 고치지 않는다. BERTScore 모델/정규화/후보 정책도 train 입력 검토가 끝나면 고정한다.

### 검증과 통과 기준

- source row↔사건↔feature slot의 추적률100%, split 중복0, 범위 밖 시간0, 비유한 입력0.
- 모달리티마다 같은 사건의 응답 구간을 사용하고 임의의1–4초 구간·질문/답변 ID 혼동0건.
- 모든 원본 사건이 보존되거나 제외 사유를 가진다. 알 수 없는 매핑을 정답처럼 처리한 항목0건.
- Train에서 고정 난수로80개 사건, 반복 질문60개, 연속 후속40개, 맞장구/unknown20개를 뽑아 총200개 입력 검토 패킷을 만든다. 중복은 제거하고 부족한 층은 전수+나머지 층에서 보충한다. PHQ 라벨과 모델 예측은 패킷에서 숨긴다.
- 확인할 것은 화자·원문 연결·질문 유형·시간 구간·부모 연결이다. 임상적 우울증 판정이 아니므로 임상 전문가 주석을 선행 조건으로 요구하지 않는다.
- 제공 speaker/시간과의 코드 연결은 전수 자동 검증한다. 사람 검토자가 없으면 AI 초안·독립 코드 검토는 가능하지만, 의미 매핑의 독립 사람 gold라고 부르지 않는다. 불확실한 것은unknown으로 유지하며 진단 실험은 잠정 mapping으로 명명할 수 있다.
- 각 참가자에 적어도 하나의 사용 가능한 질문–응답이 있고, 응답 선택 정책별 사용 사건 수·모달리티 가용률·매핑 coverage가 기록돼야 학습에 들어간다. 낮은 coverage를 성능 튜닝으로 숨기지 않는다.
- 합성 예제 `알려진 질문A→답변A→unknown질문→답변U`에서 답변U가 A슬롯에 들어가지 않는지, `질문A→답변일부→확인된맞장구→답변계속`에서는 사건A가 유지되는지 검사한다.

구현 대상: 신규 `experiments/hique3_prepare.py`, `tests/test_hique3_prepare.py`. 현재 문제 위치는 `hique2_data.py:28–75`다. 분할 검사·원본 ZIP 읽기·CLNF/OpenSMILE 유틸은 검증한 부분을 재사용한다.

## 4. 1단계: 다섯 조건으로 입력 손실의 효과를 분리

이 단계에서는 **고정 위치 AVT(F_AVT) backbone**을 사용한다. 계층 가정을 동시에 바꾸지 않는다. 기존 width4/head1/층수와 optimizer를 유지한다.

| ID | 입력 경로 | 반복 답변 | 긴 텍스트 | 비교의 의미 |
|---|---|---|---|---|
| E0 | 기존 ASR·물음표 화자·기존 매핑 | 마지막 | 앞512토큰 | 같은 공통 집합에서 다시 학습할 기준선 |
| E1 | 제공 화자·시간·텍스트 + 검증한 질문 매핑 | 마지막 | 앞512토큰 | E1−E0: **전체 입력 경로 개선의 묶음 효과** |
| E2 | E1과 동일 | 첫 번째 | 앞512토큰 | E2−E1: 첫/마지막 선택 정책 |
| E3 | E1과 동일 | 매핑된 같은 질문의 모든 답변을 시간순 보존 | 합친 텍스트 앞512토큰 | E3−E1: 반복 응답 선택 정책 |
| E4 | E3과 동일 | 모두 보존 | 블록별 encoding 후 pooling | E4−E3: 텍스트 길이 제한 처리 |

**E1−E0는 화자 구분만의 효과가 아니다.** 전사 내용·경계·매핑이 함께 달라진다. 화자 또는 ASR의 순수 기여를 따로 주장하지 않는다.

E2의 첫 답변 선택은 공개 `embedding/roberta.py:33`에서 확인한 경로를 점검하는 것이며, 비공개 최종CSV의 전처리까지 복원됐다는 뜻은 아니다. E3/E4는 정보 보존을 개선한 변형이다.

### 반복 응답과 모달리티 집계

- E1/E2는 선택된 동일 사건으로 A/V/T를 만든다. 텍스트만 첫 응답이고 음성은 마지막 응답인 조합을 허용하지 않는다.
- E3/E4의 A는 모든 해당 응답의 실제 관측 음성을 시간순 연결한 후 같은 eGeMAPS88을 계산한다. V는 같은 구간의1fps 프레임으로 평균·모분산272를 계산한다. 이 집계 정의는 추가 가정으로 기록한다.
- E3/E4의 A/V 배열·모달리티 마스크는 hash까지 동일해야 한다. 두 조건은 T의 길이 처리만 다르게 한다.
- E4: E3과 **완전히 같은 시간순 연결 텍스트**를 토큰화한 뒤 내용 토큰 최대510개, 겹침 없는 블록으로 나누고 BOS/EOS를 붙인다. frozen RoBERTa CLS를 블록별로 구한 뒤 내용 토큰 수로 가중 평균하여768차원을 유지한다. 모든 내용 토큰이 정확히 한 블록에 포함되는 것을 검사한다. 원래512토큰 이내인 슬롯은 E3과 동일한 encoding 경로·표현을 유지하고, 긴 슬롯에서만 처리 방식이 바뀌게 한다.
- E4는 텍스트를 잘라 버리지 않지만 블록 사이 상호작용을 직접 모델링하지 않는다. 완벽한 장문 이해나 원 논문 재현으로 주장하지 않는다.
- 최종 입력 형태85×88/272/768과 classifier 파라미터 수는 모든 조건에서 같다. 결측 마스크는 모달리티별로 유지한다.

구현 대상: 신규 `experiments/hique3_features.py`, `tests/test_hique3_features.py`. 현재 절단 지점 `hique2_data.py:154–164`, 재사용 검토 대상 `hique2_av.py`와 `hique2_network.py`.

## 5. 학습·평가 규칙과 실행량

- 우선 **5조건×3시드(42,13,23)=15회**, 각각100epochs를 실행한다. 기존 F_AVT 결과를 그대로 비교군으로 쓰지 않고 동일dev32에서 checkpoint를 선택하도록 재학습한다.
- Batch8, Adam0.0002, dropout0.5, 원시 특징 크기 유지, devloss 최저 checkpoint, softmax argmax를 고정한다. 표준화·모델 크기·추가 정규화·epoch은 동시에 바꾸지 않는다.
- train양성3배 증강과10질문 feature masking을 유지한다. 동일 participant/seed에는 조건을 넘어 같은 슬롯 제거 인덱스를 적용한다. 조건별 관측 슬롯 차이에 따라 실제 제거된 유효 정보량이 달라질 수 있으므로 함께 보고한다.
- 주 비교는 **E1−E0**, 주지표는 참가자 단위 Macro-F1이다. E2−E1, E3−E1, E4−E3은 사전 지정 보조 비교다. 결과가 유리한 비교만 남기지 않는다.
- 함께 볼 항목: 양성 F1, sensitivity/specificity, AUROC, confusion matrix, devloss, 증강 전 train Macro-F1, 매핑 coverage, 보존 단어/토큰 비율, feature/attention 통계.
- 3시드 결과는 방향 확인용 탐색 결과다. 실행·입력 검증에 문제가 없으면 성능 방향과 무관하게 모든5조건에 시드37/79를 추가한다. **총25회**이며, 좋은 조건에만 시드를 추가하지 않는다.
- 5시드 평균·SD와 각시드 값을 모두 보고한다. 시드별 F1 차이 평균에 대해 같은 참가자를 두 조건에서 함께 재표집하는 bootstrap2,000회를 사용할 수 있으나, checkpoint를 선택한 dev를 재사용한 **탐색적 구간**이다. 새로운 일반화 성능의 확증 CI로 부르지 않는다.
- 어느 조건을 최종 후보로 선택할지는 결과표 작성 후 결정하되, 그 선택과 추정 성능이 동일dev를 사용했다는 한계를 표시한다. 추가 개선 실험은 별도 프로토콜로 분리한다.

기술 오류면 원인을 고치고 영향을 받은 조건을 모두 재실행한다. 성능이 낮다는 이유로 seed·표본·threshold를 바꾸지는 않는다. 전처리·모델·환경·증강·명단·중간 특징 hash를 고정한다.

## 6. 2단계: 더 세밀한 원인 분리와 계층 실험

이 단계는 첫15회에 자동으로 포함하지 않는 후속 작업이다.

### 전사 내용만 분리하는 추가 비교

E1의 제공 화자·답변 경계·질문 매핑·A/V 특징을 그대로 고정하고, 그 답변 음성만 로컬 Whisper로 다시 전사한 텍스트를 넣는다. 언어en/모델/디코딩을 사전 고정한다. 이 조건과 E1의 차이는 **고정된 응답 구간에서 ASR텍스트와 제공텍스트의 차이**로 해석할 수 있다. 기존E0과 비교해서 화자 효과만 분리됐다고 주장하지 않는다.

### 계층 모델

저자에게 요청할 구체 자료: 비식별 `_TRANSCRIPT_FINAL.csv` 예시, 질문별 특징 예시, 반복 응답 집계 규칙, 직전 질문/부모/root의 tensor 변환, 실행config/checkpoint. 문의 초안까지만 준비하고 지시 없이 보내지 않는다.

- 자료를 확보하면 먼저 해당 예시의 tensor를 맞춘 후, 고정 위치와 논문 계층 구현을 비교한다.
- 자료가 없으면 최근root 상속·직전질문 관계 등을 각각 **가설 모델**로 명명한다. 논문 구현이라고 단정하지 않는다.
- 모든 답변을 합친85개 질문 슬롯은 하나의 질문이 여러 부모 아래 나타나는 관계를 하나의 parent ID로 표현할 수 없다. 따라서 **E4에 마지막 parent 하나만 붙여 '정보를 모두 보존한 계층 모델'이라고 하지 않는다.**
- 저자 방식이 없을 때 사건별 표현으로 이동하면 sequence 길이·position/attention mask·pooling도 달라질 수 있다. 이 경우 정보량과 파라미터 수를 맞춘 별도 설계가 필요하며, 이번 고정85슬롯 원인 비교와 분리한다.

## 7. 실행 파일 및 검증 산출물

예정 파일:

- `hique3_prepare.py`:제공전사 사건 표·매핑·출처·입력검토 패킷.
- `hique3_features.py`:첫/마지막/전체 선택과 동일모달리티 구간, 텍스트 chunk pooling.
- `hique3_train.py`:고정cohort·비교목록·seed·checkpoint·dev-only 실행. 기본 경로에서는 `full_test_split.csv`를 읽지 않는다.
- `hique3_report.py`:모든조건/seed의 성능·coverage·정보손실과 변화량. 원본논문 대비 가정표 포함.
- 테스트:원문 row 연결,맞장구 뒤 응답 유지,반복/연속후속,중첩구간,NaN,블록 경계,모든토큰 정확히한번 보존,모달리티 interval 동기화,같은seed증강 일치,test outcome 미접근.

기존 로직을 고쳐 과거 산출물의 hash를 깨지 않는다. 검증된 함수 재사용은 가능하지만, `hique_network.load_patched_upstream()`의 기존manifest 쓰기 부작용처럼 새 실행이 이전 폴더를 수정하는 경로는 새 출력으로 분리하거나 차단한다. 필요한 환경·가중치는 기존 로컬 캐시를 우선 활용하고 외부 LLM API를 사용하지 않는다.

## 8. 완료 기준과 기대하는 결론

- 참가자·원문·질문·답변·모달리티 구간이 추적되고, 미확정 매핑과 버려지는 정보가 숨겨지지 않는다.
- E1−E0의 전체 입력 경로 효과, E2/E3의 반복 답변 선택 효과, E4−E3의 길이 처리 효과를 정해진 비교로 보고한다.
- 향상이 없으면 이를 결과로 남기고 모델 용량 확대·epoch 추가로 덮지 않는다. 입력 coverage·mapping·간단한 텍스트 기준모델을 다음 가설로 검토한다.
- 성능이 좋아져도 E3/E4를 원 논문의 정확 재현이라고 부르지 않는다.
- 임상적 증상 gold를 새로 만들지 않는다. 제공 PHQ 선별 라벨 예측과 입력 처리 검증의 범위다.

첫 실행은 **입력 사건 표·검토 패킷 → 같은집합의5조건×3시드15회**를 권한다. 입력 문제와 정보 손실의 효과를 확인한 뒤에야 계층 모델을 다시 비교하는 것이 현재 증거에 맞는 순서다.
