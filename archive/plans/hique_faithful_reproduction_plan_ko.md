# HiQuE 원 실험에 충실한 재현 계획

> 보존된 과거 계획이다. 실행 여부와 실제 조건은 [실험 목록](../../experiments/README.md)의 결과 기록을 우선한다.

후속 설계: 사용자 요청에 따라 440 제외를 확정한 [2026-09-29 실험 설계](hique_experiment_design_excluding440_ko.md)가 데이터 범위와 실행 순서를 구체화한다.

작성일: 2026-09-28. 이 문서는 계획이며 새 학습·평가는 실행하지 않았다.

## 목표와 해석

논문 arXiv:2408.03648v1 및 공개 저장소 commit `24c553bf2666b442ae5b0e3490b998a5d4493559`의 실험 조건을 추적 가능한 근거로 복원한다. 목표는 Macro-F1 0.79라는 숫자에 맞추는 것이 아니라, 같은 입력·처리·모델·평가 조건을 구현하고 결과가 달라도 보고하는 것이다.

기존 실행은 공개 네트워크를 이용한 변형 실험이다. 고정 질문 ID를 사용하는 현재 입력은 논문 §4.3의 선행 질문과 후속 질문 간 계층 관계를 별도로 표현하지 않는다. 기존 결과와 feature/cache는 비교·감사를 위해 보존하며 새 실험으로 덮어쓰지 않는다.

근거: [논문](https://arxiv.org/abs/2408.03648v1), [공개 코드](https://github.com/JuHo-Jung/HiQuE).

## 1. 실험 명세와 불일치 표 작성

각 항목에 논문 페이지/절, 공개 코드 파일/행, 실제 선택, 불확실성을 연결한다. 논문과 코드가 충돌하면 임의로 두 방식을 섞지 않는다. 논문 재현을 위한 선택과 공개 코드 실행을 위한 호환성 수정을 구분한다. 저자 확인이 없으면 선택한 해석을 가정으로 표시한다.

반드시 확정할 항목:

- 실제 train/dev/test ID와 라벨 버전. 현재 로컬 공식 명단은 107/35/47명이다.
- 전사 출처(Whisper/제공 전사), Whisper 체크포인트, 화자 구분, 발화 병합, 질문·응답 구간 경계.
- 85개 질문의 정확한 순서·topic/type 및 반복 질문·후속 질문 연쇄 처리.
- 계층 position의 정의와 부모 topic ID를 어떤 tensor에 어떻게 반영하는지.
- BERTScore 체크포인트/layer/tokenizer/버전 및 질문 대응 규칙. 코드의 사용되지 않는 BERT 객체를 실제 BERTScore 모델로 오인하지 않는다. 현재 공개 similarity.py는 argmax를 사용하며 기존 자체 0.75 cutoff와 다르다.
- RoBERTa 체크포인트, frozen/fine-tuned, CLS 위치, 길이 제한·긴 응답 처리.
- openSMILE 구성·버전, CLNF 좌표/단위·프레임 표본화·분산 정의·결측 처리.
- 정규화 범위, 모달리티별 결측, augmentation의 시점·대상·반복 방식.
- 모델 차원/head/layer/position, optimizer 세부값, seed, 마지막 불완전 batch 처리, checkpoint, 지표 집계.

확인된 충돌: 논문은 100 epochs/배치8이나 hique.py CLI 기본은 50 epochs/배치8이며 파일 상단에는 별도 배치2가 있다. 공개 visual 경로와 논문 CLNF 설명이 다르고, 현재 loader에는 참가자 누적·결측 차원 문제가 있다. CLI 실행 시 실제 적용되는 값을 기준으로 기록한다.

**완료 기준:** 핵심 항목이 근거 있는 확정 또는 명시적 미확정으로 분류되고, 미확정 값을 확정 사실처럼 구현하지 않는다.

## 2. 저자 자료 요청 목록 준비

다음 자료의 존재 여부와 공개 제공 가능성을 먼저 확인한다. 필요하면 문의 초안을 작성하되 사용자 지시 없이 연락하지 않는다.

1. Table 1을 생성한 실제 commit/config와 실행 명령, seed 및 반복 집계 방식.
2. ID별 split, 사용한 라벨 파일 버전 또는 hash.
3. 질문 코드북과 공개 similarity.py가 요구하는 TRANSCRIPT_FINAL.csv의 비식별 예시/schema.
4. 주질문→후속 질문의 원본 행부터 hierarchy tensor까지 연결되는 예시.
5. 전사/ASR/BERTScore/RoBERTa/openSMILE 설정 및 정규화·결측 규칙.
6. 공유 가능한 feature 예시·hash·통계, 최종 checkpoint와 평가 스크립트.

**한계:** 핵심 자료가 없으면 '엄밀히 동일한 실험'으로 인증할 수 없다. 논문 명세에 따른 구현과 미확정 가정 목록을 결과에 함께 제시한다.

## 3. 데이터와 평가 범위 고정

- 원본 ZIP/CSV hash와 공식 split별 ID를 확인한다. 숫자가 같다는 이유만으로 동일 cohort라고 판단하지 않는다.
- 440은 기존에 확인된 손상 상태다. 정상 원본을 확보하지 못하면 full189 재현은 불가능하다고 명시한다. 임의 데이터나 특징으로 보충하지 않는다.
- 451/458/480은 원음에 질문 복원이 가능한 정보가 있는지 먼저 확인한다. 가능할 때만 원 논문 절차에 맞춰 복구하며, 없으면 발화를 추측하지 않는다.
- 300은 원래 test 소속이다. 이전 사례 노출을 이유로 제외한 기존 정책과 원 실험 cohort 일치 요구를 구분해 결정하고, 노출 이력을 남긴다.
- 402 영상의 실제 종료 시각, 409 binary/score 불일치, 사용자 제공 test 라벨 출처를 기록한다. binary를 임의로 재작성하지 않는다.
- 기존 test45 결과를 이미 봤으므로 같은 test를 '처음 보는 평가'라고 부르지 않는다. 이후 구현 변경 근거는 논문·저자 자료·train/dev 검증으로 제한한다.
- 공식 test 후속 점수는 노출된 benchmark에 대한 재현 결과로 보고한다. 새로운 일반화 주장은 별도로 확보한 미노출 외부 평가가 있어야 한다. 현재 데이터를 재분할한다고 노출 이력이 사라지는 것은 아니다.

**완료 기준:** 사용/제외 ID, 사유, 라벨 출처, 기존 노출과 모든 평가 제한이 학습 전에 문서화된다.

## 4. 질문 계층을 작은 예제로 먼저 검증

전체 feature 추출 전에 합성 대화와 train의 소수 사례로 다음 중간 자료를 확인한다.

`원본 발화 → 화자/시간 → 질문 topic/type → 선행 질문 연결 → 응답 구간 → hierarchy/position → 실제 모델 입력`

- 주질문 뒤 후속 질문, 후속 질문 뒤 후속 질문, 화제 전환, 반복 주질문, 질문 부재를 다룬다.
- '더 설명해 주세요'가 서로 다른 주제 뒤에 나올 때, 논문에 명시된 관계 차이가 실제 모델 입력에 반영되는지 확인한다.
- 따라 붙는 parent ID를 tensor로 전달하지 않고 메타데이터에만 기록하는 구현은 통과시키지 않는다.
- 85개 고정 질문 칸과 실제 대화 순서를 혼동하지 않는다. 반복 응답을 합칠지/분리할지는 근거에 따라 정한다.
- 음성·영상·텍스트가 동일한 질문/응답 단위에 대응하는지 시간 구간과 실제 발화를 대조한다.

**완료 기준:** 예시 입력에서 기대하는 관계·구간·배열을 사람이 읽을 수 있고, 경계 사례 검증을 통과한다. 저자 중간 산출물이 있으면 직접 비교한다.

## 5. 논문 특징·네트워크·학습 절차 복원

- 명시된 A 85×88, V 85×272, T 85×768 입력을 구현하고 feature 이름·순서·단위·dtype를 기록한다.
- 이전 실행의 공통 A/V/T mask, 자체 유사도 cutoff, 임의 품질 임계값, 표준화는 원 실험 근거가 확인되지 않는 한 충실 재현 조건에 자동 승계하지 않는다. 모달리티 하나의 결측이 다른 모달리티의 유효 정보를 제거하는지도 점검한다.
- NaN·손상 데이터는 조용히 통과시키지 않는다. 처리 근거가 없으면 명시적인 재현 편차로 기록한다.
- 공개 모델의 4차원 임베딩/1-head 설정 등과 논문 tensor 설명을 대조하고, 정확한 모델 parameter 수와 shape trace를 남긴다.
- 실행 불능 오류 수정(반환형·loader·호환성)과 모델링 변경(정규화·mask·차원)은 별도 diff로 관리한다.
- 명시된 학습 값은 100epochs, batch8, Adam lr0.0002, dropout0.5, train 양성3배·85개 중10개 질문 masking이다. 공개 실행의 최저 dev loss checkpoint 선택을 기록하되 원 결과 설정과 동일한지 확인한다.
- augmentation 복사본은 train 내부에만 두고, preprocessing을 데이터에서 학습해야 한다면 train만 사용한다. 원 구현의 누수가 발견돼도 재현 목적으로 정상 benchmark에 섞지 않고 별도 문제로 보고한다.
- 작은 train subset 과적합 검사, shuffle-label sanity check(train/dev 내부), 예측 분포·gradient·저장/복원 및 동일 seed 반복을 검사한다. 이는 실행 오류 진단이며 논문 충실도를 대신하지 않는다.

**완료 기준:** 전처리 대응 예시, shape trace, 모델 설정 및 오류 수정 목록을 확인한 뒤에만 본학습으로 진행한다.

## 6. 본실험과 보조실험의 순서

1. 먼저 AVT 한 조건으로 논문 Table 1의 HiQuE 행을 대상으로 한다. 원 seed/반복 정책이 확인되면 따른다. 미확정이면 실행 전에 명시한 정책을 사용하고 저자 정책으로 주장하지 않는다.
2. 이후 T 단독을 확인한다. 논문 Fig.4의 텍스트 성능은 결합 이전 처리가 맞는지 살피는 비교 근거다. test 숫자에 맞춰 checkpoint나 전처리를 선택하지 않는다.
3. A/V/AV/AT/VT 등 모달리티 분석과 계층 embedding·증강 ablation은 본경로 검증 후 별도 실행한다. 원 baseline 구조와 통제 branch 삭제를 구분한다.
4. 추가 5-seed 결과는 안정성 분석으로 보고하고, 논문 단일/미상 집계 점수와 동일한 집계로 취급하지 않는다. 최고 seed만 선택하지 않는다.
5. 충실 재현 경로가 고정된 뒤에만 기존 변형과 차이를 한 가지씩 바꾸는 train/dev 진단을 수행한다. 재현 확인과 성능 개선을 같은 실험으로 섞지 않는다.

## 7. 평가와 완료 기준

- 논문 Table 1에 맞춰 macro precision/recall/F1, weighted precision/recall/F1, G-mean을 계산한다. G-mean 정의도 확인한다. Positive F1·AUROC·confusion matrix는 보조 결과다.
- 저장한 참가자별 확률과 label에서 지표를 독립 재계산한다. argmax/tie 처리, truth/pred 순서, 참가자 단위를 점검한다.
- 단일 seed, seed별 지표 평균, 확률 ensemble은 별개로 보고한다. 원문 값과 동일 cohort/지표/집계인지 표시한다.
- 코드·환경·원본/feature hash·split·augmentation·checkpoint·예측·epoch 로그를 보관한다. 모든 수정과 test 접근 이력을 남긴다.
- 완료 여부는 0.79 달성이 아니라 조건 추적성, 핵심 hierarchy 구현, 입력·평가 검증, 남은 편차의 공개로 판단한다. 원 feature/checkpoint가 제공되면 일치 여부가 가장 강한 확인 근거다.

## 실행 우선순위와 산출물

첫 작업은 대규모 재학습이 아니라 **명세 대조표 + 저자 문의 초안 + 계층 입력 예시**다. 이 셋이 정리된 다음 전처리·모델 구현과 본학습으로 넘어간다.

예정 산출물: 근거별 명세표, 불확실성 목록, 고정 cohort/protocol, 질문 계층 검증 예시, 최소 수정 patch, 환경 lock, 중간 feature 검증, 학습 로그 및 논문 대비 결과표.

현재 승인 범위는 계획 수립이다. 이 문서를 작성하며 기존 모델·feature·test 결과는 변경하거나 재실행하지 않았다.
